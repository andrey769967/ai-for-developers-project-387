# Мьютекс на создании Booking

Проверка Overlap и вставка Booking выполняются под одним процессным `async-mutex`, чтобы два одновременных запроса на один Slot не могли оба пройти проверку. Альтернативы — транзакция с ограничением в БД или оптимистичная проверка-и-запись — недоступны: хранилище в памяти (ADR-0001) не даёт ни транзакций, ни уникальных индексов, поэтому мьютекс и есть граница корректности.

## Consequences

- Гарантия действует в пределах одного процесса. Второй экземпляр сервера или кластер сломает её молча.
- Чтение Availability намеренно не блокируется: оно не меняет состояние, а устаревший Slot отсекается повторной проверкой при создании Booking.
- При переезде на БД мьютекс надо убрать, а не оставить «для надёжности»: двойная защита скрывает ошибки в транзакции.
