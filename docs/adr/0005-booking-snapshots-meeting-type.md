# Booking хранит снимок MeetingType

Booking сохраняет `meetingTypeName` и вычисленный `endTime` на момент создания, а не восстанавливает их из текущего MeetingType. Так история записей остаётся читаемой после переименования или удаления типа, админский список не требует join, а занятый интервал самодостаточен для проверки Overlap.

## Consequences

- Изменение Duration у MeetingType не меняет уже созданные Booking — это намеренно, а не рассинхронизация.
- После удаления MeetingType у Booking остаётся висячий `meetingTypeId`: история отображается, но Slot для этого типа больше не выдаются — сейчас это 404 без предупреждения в UI.
- Снимок — копия, а не кэш: «починить» расхождение с текущим MeetingType нельзя, не потеряв историческую достоверность.
