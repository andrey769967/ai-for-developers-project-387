# Вызов агента из комментария

Одна команда в комментарии к issue или pull request запускает репозиторного агента.
Воркфлоу живёт в [`.github/workflows/agent-comment.yml`](../../.github/workflows/agent-comment.yml),
промпт — в [`.github/agent/prompt.md`](../../.github/agent/prompt.md).

## Как вызвать

Оставьте комментарий, первый токен которого — `/agent`, дальше произвольная задача:

```text
/agent подготовь спеку на смену формата слотов
/agent разбей issue #12 на тикеты
/agent реализуй спеку #10 и её тикеты
```

Агент читает `AGENTS.md`, глоссарий и ADR, выбирает подходящий скилл и явно его
загружает:

| Запрос | Скилл |
|--------|-------|
| спецификация, дизайн, требования | `to-spec` |
| разбивка на тикеты, планирование | `to-tickets` |
| реализация спецификации и тикетов | `implement-spec` |

Для других задач агент работает напрямую по обычным правилам репозитория.
Скиллы с `disable-model-invocation: true` не видны модели автоматически, поэтому
промпт предписывает называть их ID явно (`@to-spec` и т. д.).

## Кто может запускать

Только авторы комментариев с association `OWNER`, `MEMBER` или `COLLABORATOR`.
Комментарии посторонних и ботов игнорируются: воркфлоу может пушить код и писать
в трекер. Параллельные запуски для одного issue не отменяются (`concurrency` с
`cancel-in-progress: false`), чтобы не обрывать начатую реализацию.

## Что делает воркфлоу

1. Проверяет триггер `/agent` и права автора.
2. Чекхаутит репозиторий (для PR — голову PR), собирает промпт из текста комментария
   и `.github/agent/prompt.md`.
3. Устанавливает OpenCode CLI (`npm install -g @opencode/cli`) и запускает
   `opencode run --model "$OPENCODE_MODEL"`.
4. Агент пишет короткий бриф в `.scratch/agent-response.md`; воркфлоу публикует его
   комментарием в ту же нить с пометкой об исходе шага. Повторных комментариев от
   самого агента нет.
5. При падении публикуется сообщение с ссылкой на лог запуска, чтобы причина была
   видна без чтения логов.

## Настройка в GitHub

В `Settings → Secrets and variables → Actions` нового репозитория:

- **Secret** `OPENCODE_API_KEY` — ключ OpenCode Console. Вместо него можно задать
  ключ другого провайдера (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`,
  `OPENROUTER_API_KEY`) — все они пробрасываются в окружение агента.
- **Variable** `OPENCODE_MODEL` — модель в формате `provider/model`. По умолчанию
  `opencode/deepseek-v4.1-flash-free`; модель и аккаунт должны быть доступны с ключом.

Без ключа шаг `Run agent` упадёт, но комментарий с ссылкой на лог всё равно
будет опубликован.

## Границы

- Воркфлоу открыт только для доверенных авторов: он держит токен с записью в
  `contents`, `issues` и `pull-requests`.
- Человеческого чекпоинта внутри запуска нет: агент не задаёт вопросов и работает до
  конца. Если нужен спорный или необратимый шаг, оставьте задачу человеку.
- Для fork-PR секреты и write-токен GitHub не выдаёт, поэтому автоматический агент
  рассчитан на комментарии внутри основного репозитория.
- Обязательный файл Хекслета `.github/workflows/hexlet-check.yml` воркфлоу не трогает.
