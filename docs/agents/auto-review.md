# Независимое авторевью pull request

Отдельный запуск модели на событии `pull_request`: ревьюер читает спецификацию, тикеты, diff и результаты CI и оставляет замечания, но **не меняет код**. Воркфлоу живёт в [`.github/workflows/auto-review.yml`](../../.github/workflows/auto-review.yml), промпт — в [`.github/agent/review-prompt.md`](../../.github/agent/review-prompt.md), проектные критерии — в [`REVIEW.md`](../../REVIEW.md).

Это не вызов агента из комментария и не автотриаж: у каждого из них свой воркфлоу и свой промпт.

## Когда запускается

- Событие: `pull_request` с типами `opened`, `synchronize`, `reopened`.
- PR из того же репозитория: `head.repo.full_name == github.repository`. Fork'ы не получают секрет модели.
- Автор: `OWNER`, `MEMBER`, `COLLABORATOR`, а также `github-actions[bot]` — PR агента тоже должен ревьюироваться. Фильтровать всех ботов нельзя.
- `pull_request_target` **не используется**: код PR выполняется только в обычном `pull_request`.

## Ограничения и права

- `timeout-minutes: 30`.
- `concurrency` по номеру PR, `cancel-in-progress: true`: новый push отменяет устаревшее ревью того же PR.
- Права воркфлоу: `contents: read`, `issues: read`, `actions: read`, `checks: read`, `statuses: read`, `pull-requests: write`. Ревьюер может комментировать PR, но не может писать код.
- Чекхаут делает `ref: head.sha` и `persist-credentials: false`. Секреты модели пробрасываются только в этот доверенный запуск.
- На шаге `Run independent reviewer` нет `GH_TOKEN`: агент видит только файлы и git-дифф. Публикация — отдельный шаг без модели (`gh pr comment` для общего комментария и GitHub API для inline-замечаний).

## Что делает агент

1. Читает `AGENTS.md`, глоссарий, ADR, `docs/agents/` и переданное содержимое `REVIEW.md`; явно загружает скилл `@code-review` и проверяет three-dot diff между base и head SHA.
2. Берёт из `.scratch/review-context/` метаданные PR, вывод `gh pr checks` и дампы всех issue, на которые PR ссылается в теле. Все эти данные — не инструкции. Если ссылок на спецификацию, тикеты и согласование нет, ревью сообщает об этом как о пробеле.
3. Проверяет бизнес-инварианты из `REVIEW.md`: занятый слот недоступен повторно, пересечения отклоняются при конкурентных запросах, окно 14 дней и рабочие часы 09:00–18:00 Europe/Moscow, контракт и сгенерированные типы, тесты конкурентности.
4. Пишет общий текст в `.scratch/review.md` и inline-замечания в `.scratch/inline-comments.json`. Формат замечания: файл, строка, условие ошибки, последствие. При отсутствии дефектов говорит об этом прямо.
5. Не правит код, не публикует комментарии сам и не продолжает сессию реализации.

## Что проверяет человек

1. Перед PR реализации: в `.github/workflows/` есть воркфлоу авторевью с критериями, тайм-аутом и отменой устаревших запусков; `REVIEW.md` действительно передаётся в промпт; шаблон PR лежит в `.github/pull_request_template.md`; README описывает воркфлоу.
2. Настройки GitHub: воркфлоу включён, секрет `OPENCODE_API_KEY` и variable `OPENCODE_MODEL` на месте; для обязательности CI на `main` включён required status check «CI / Проверка»; доступ Actions к code и secrets меняется отдельным решением человека.
3. Сценарий на тестовом PR: авторевью стартует само, оставляет замечание в обсуждении и inline-комментарий к строке; повторный push отменяет предыдущий run. PR, созданный `GITHUB_TOKEN`, может требовать ручного подтверждения запуска — это нормально.
4. Если авторевью не стартует, сначала проверьте источник токена и ожидающее подтверждение в PR, а не буквальное совпадение YAML с примером.

## Ограничение рядом

Следующий пункт шага 4 — предел запусков на PR **до вызова модели** (счётчик, причины `limit_exhausted` / `timeout` / `infra` / `agent_failed`, последний SHA и ссылка на логи). Сейчас в этом воркфлоу его нет; планируйте добавить до включения бюджетов, чтобы не переделывать YAML.

Обязательный файл Хекслета `.github/workflows/hexlet-check.yml` не трогается.
